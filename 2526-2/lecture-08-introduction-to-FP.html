1.
Tổng quan về lập trình hàm

Lập trình hàm là gì?

Định nghĩa

Lập trình hàm (Functional Programming - FP) là một mô hình lập trình nơi tính toán tiến hành thông qua việc viết lại thuật ngữ thay vì sửa đổi trạng thái.

  • Biểu thức thay vì trạng thái: Không có khái niệm ô nhớ thay đổi, mọi thứ đều là đánh giá giá trị.
  • Tính nhất quán: Khi môi trường đã cố định, một biểu thức luôn luôn biểu thị cùng một giá trị.

Lập trình hàm và Lập trình mệnh lệnh

Đặc điểm Lập trình mệnh lệnh Lập trình hàm (FP)
Mô hình gốc Kiến trúc Von Neumann (Lệnh + Bộ nhớ) Phép tính Lambda
Cơ chế chính Gán biến & thay đổi trạng thái Đánh giá biểu thức
Thứ tự thực hiện Rất quan trọng Ít quan trọng
Side Effects Phổ biến Hạn chế hoặc không có

Trạng thái và Bất biến

C++ (Cập nhật biến):


      int x=10;
      x = x + 5; // Trạng thái x thay đổi
      x = x * 2; // Giá trị cũ bị ghi đè

FP (Tạo giá trị mới):


      let x = 10
      let y = x + 5 -- x vẫn là 10
      let z = y * 2 -- y vẫn là 15
Trực quan: Mệnh lệnh giống như ghi đè lên bảng phấn. FP giống như chụp một loạt các bức ảnh, mỗi bức ảnh là một giá trị cố định.

Vì sao cần học FP?

  • Dễ suy luận: Không có biến ẩn thay đổi giá trị, mã nguồn trở nên minh bạch.
  • Dễ kiểm thử: Hàm thuần khiết luôn cho cùng kết quả với cùng đầu vào, không cần giả lập phức tạp.
  • Dễ tái sử dụng: Các hàm độc lập có thể lắp ghép như các khối Lego.
  • Hiện đại: Hầu hết các ngôn ngữ phổ biến (C++, Java, Python, JS) đều đang bổ sung các tính năng FP mạnh mẽ.

FP trong thực tế

Ngôn ngữ FP thuần

  • Haskell: Chuẩn mực của sự thuần khiết.
  • Lisp/Scheme: Cội nguồn của FP.
  • OCaml/Erlang: Ứng dụng trong hệ thống tài chính & viễn thông.

Đa mô hình (Hybrid)

  • C++: Lambda (C++11), Ranges (C++20).
  • Python: map, filter, lambda.
  • JavaScript: const, arrow functions, xử lý mảng hàm.

2.
Các nguyên lý cốt lõi

Hệ thống tư duy

Các trụ cột chính
  • Tính toán bằng biểu thức: Mọi đơn vị code đều trả về giá trị.
  • Hạn chế thay đổi trạng thái: Giữ cho dữ liệu ổn định và nhất quán.
  • Ưu tiên hàm thuần và dữ liệu bất biến: Đảm bảo tính dự đoán được.
  • Xây dựng bằng tổ hợp hàm: Lắp ghép các khối logic nhỏ thành hệ thống lớn.

“Từ các nguyên lý này, FP hướng đến chương trình dễ dự đoán, dễ kiểm thử và dễ tổ hợp.”

Hàm thuần khiết

Nguyên tắc vàng
  • Với cùng đầu vào, hàm luôn cho cùng đầu ra.
  • Không gây ra tác dụng phụ: Không thay đổi bất kỳ thứ gì bên ngoài phạm vi của hàm.
✅ Pure:
square(x) = x * x
(Chỉ tính toán và trả về giá trị)
❌ Impure:
square(x) { print(x); return x*x; }
(Vừa tính vừa in ra màn hình/sửa biến global)

Minh bạch tham chiếu:

Có thể thay thế lời gọi hàm bằng giá trị kết quả mà không làm đổi nghĩa chương trình.

Tính bất biến

  • Không sửa trực tiếp dữ liệu cũ: Một khi dữ liệu được tạo ra, nó không bao giờ thay đổi.
  • Tạo ra giá trị mới: Thay vì sửa trực tiếp, ta tạo ra giá trị mới phản ánh các thay đổi cần thiết.
Old: [1, 2, 3] --(add 4)--> New: [1, 2, 3, 4]

Mảng cũ giữ nguyên, tạo mảng mới chứa giá trị thay đổi.

Lưu ý kỹ thuật: Các ngôn ngữ FP hiện đại sử dụng Structural Sharing (chia sẻ cấu trúc) để tối ưu bộ nhớ thay vì sao chép toàn bộ dữ liệu.

Hàm bậc cao

Ý chính
Trong FP, hàm được xem như một giá trị và có thể được truyền vào, trả về, hoặc lưu trữ như dữ liệu thông thường.
  • Hàm bậc cao: Nhận hàm khác làm tham số hoặc trả về một hàm mới.
  • Tổ hợp hàm: Khả năng ghép các hàm nhỏ để tạo ra xử lý phức tạp hơn, ví dụ: f(g(x)).

    .

Ví dụ hàm bậc cao

Yêu cầu: Thực hiện hàm f hai lần trên giá trị x.

Cách 1: Cấu trúc truyền thống


      // Dùng con trỏ hàm (Function Pointer)
      int square(int x) {
          return x * x;
      }
      
      int applyTwice(int (*f)(int), int x) {
          return f(f(x));
      }
      
      // Gọi hàm:
      int res = applyTwice(square, 3); 
      // (3*3)^2 = 81

Cách 2: Cấu trúc hiện đại


      // Dùng Lambda và Generic
      auto square = [](int x) { 
          return x * x; 
      };
      
      auto applyTwice = [](auto f, int x) { 
          return f(f(x)); 
      };
      
      // Gọi hàm:
      int res = applyTwice(square, 3);
      // (3*3)^2 = 81

*Nhận xét: Cách 2 linh hoạt hơn nhờ khả năng tự suy luận kiểu (auto) và cú pháp ngắn gọn.

Đệ quy

Trong FP, đệ quy là một cơ chế quan trọng để biểu diễn lặp mà không cần cập nhật biến đếm như trong vòng lặp truyền thống.

Lập trình mệnh lệnh: Vòng lặp


        int factorial(int n) {
            int result = 1;
            for(int i = 1; i <= n; i++)
                result *= i; // Cập nhật biến
            return result;
        }

Lập trình hàm: Đệ quy


        int factorial(int n) {
            // Không dùng biến đếm, không cập nhật
            if (n <= 1) return 1;
            return n * factorial(n - 1);
        }

Cấu trúc an toàn của đệ quy

Để tránh lỗi tràn ngăn xếp hoặc vòng lặp vô hạn, một hàm đệ quy luôn phải được xây dựng từ hai thành phần sống còn:

1. Điểm dừng

Là trường hợp đơn giản nhất mà hàm có thể trả về kết quả ngay lập tức không cần tính toán thêm.

  • Ngăn chặn đệ quy vô hạn.
  • Thường nằm ở đầu hàm.

        if (n <= 1) return 1;
2. Bước đệ quy

Là phần logic chia nhỏ bài toán lớn thành các bài toán con tương tự nhưng có kích thước nhỏ hơn.

  • Gọi lại chính nó.
  • Tiến dần về phía điểm dừng.

        return n * factorial(n - 1);
⚠️ Cảnh báo: Nếu thiếu Điểm dừng hoặc Bước đệ quy không tiến về điểm dừng, chương trình sẽ gây treo hệ thống hoặc cạn kiệt bộ nhớ Stack.

Tối ưu hóa đệ quy

Đệ quy đuôi

Là trường hợp lời gọi đệ quy là hành động cuối cùng của hàm. Trình biên dịch có thể tái sử dụng vùng nhớ Stack, giúp hiệu năng tương đương vòng lặp.


        // Sử dụng biến tích lũy để tối ưu
        int factorialHelper(int n, int acc) {
            if (n <= 1) return acc;
            // Lời gọi đệ quy là lệnh cuối cùng, không còn tính toán sau đó
            return factorialHelper(n - 1, n * acc); 
        }
        
        int factorial(int n) {
            return factorialHelper(n, 1);
        }

3.
Các khái niệm nền tảng

Phép tính Lambda

Nền tảng lý thuyết

Hệ thống hình thức do Alonzo Church phát triển, dùng để mô tả hàm, áp dụng hàm và quá trình tính toán trong lập trình hàm.

  • Vai trò: Cung cấp mô hình tối giản để biểu diễn mọi tính toán chỉ thông qua hàm.
  • Cú pháp cốt lõi:
    • Abstraction ($\lambda x.M$): Định nghĩa hàm ẩn danh với tham số $x$ và thân hàm $M$.
    • Application ($E_1 E_2$): Áp dụng hàm $E_1$ lên đối số $E_2$.

Biến tự do và Ràng buộc

Để hiểu cách hàm hoạt động, ta cần phân biệt cách biến được định nghĩa:

Biến ràng buộc

Biến được khai báo bởi $\lambda$ và chỉ có ý nghĩa trong phạm vi thân hàm đó.

Biến tự do

Biến xuất hiện trong thân hàm nhưng không được khai báo bởi $\lambda$ của hàm đó.

Ví dụ: $\lambda x. x + y$

($x$ là Biến ràng buộc, $y$ là Biến tự do)

*Đây là cơ sở để hiểu về bao đóng và cơ chế bắt biến.

Bao đóng (Closure)

Định nghĩa bản chất

Closure là một hàm đi kèm với một môi trường lưu giữ các biến tự do mà hàm đó cần để hoạt động.

Hàm thông thường


      bool checker(int value, int threshold) {
          return value > threshold;
      }
      // Mỗi lần gọi đều phải truyền threshold
      checker(120, 100); 
      checker(50, 100);
➜ threshold phải luôn đi kèm lời gọi hàm.

Closure (Lambda Capture)


      int threshold = 100;
      // "Gói" luôn threshold vào trong hàm
      auto isOverThreshold = [threshold](int value) {
          return value > threshold;
      };
      // Bây giờ hàm chỉ cần 1 tham số
      isOverThreshold(120); // true
➜ threshold đã trở thành một phần của hàm.
Closure = Mã lệnh hàm + Môi trường (giá trị được capture)

Currying

Kỹ thuật biến đổi một hàm nhận nhiều tham số thành một chuỗi các hàm, mỗi hàm nhận đúng 1 tham số.

Hàm thông thường


      int add(int x, int y) {
          return x + y;
      }
      // Gọi hàm: truyền tất cả tham số
      int res = add(5, 10);
➜ Phải có đủ 5 và 10 mới tính được.

Hàm đã Curried


      auto curried_add = [](int x) {
          return [x](int y) { return x + y; };
      };
      // Gọi hàm: chuỗi các lời gọi ( )
      int res = curried_add(5)(10);
➜ curried_add(5) trả về một hàm mới!
Partial Application: giúp tạo hàm mới bằng cách cố định trước một phần tham số của hàm ban đầu.

4.
Đánh giá

Ưu điểm của FP

  • Dễ suy luận: Do tính minh bạch tham chiếu, ta có thể hiểu hàm mà không cần biết trạng thái toàn cục của hệ thống.
  • Dễ kiểm thử: Các hàm thuần khiết độc lập hoàn toàn, không cần giả lập môi trường phức tạp.
  • Tính tái sử dụng: Hàm bậc cao và kết hợp hàm tạo ra các thành phần cực kỳ linh hoạt.
  • Song song hóa: Tính bất biến giúp tránh hoàn toàn xung đột dữ liệu giữa các luồng.

Hạn chế và Thách thức

  • Hiệu năng: Việc sao chép dữ liệu để đảm bảo bất biến có thể gây tốn bộ nhớ và giảm tốc độ.
  • Độ dốc học tập: Yêu cầu lập trình viên từ bỏ các thói quen mệnh lệnh (vòng lặp, gán giá trị) để chuyển sang tư duy hàm.
  • Khi nào dùng: FP cực kỳ hiệu quả cho xử lý dữ liệu, trình biên dịch, hệ thống phân tán; nhưng có thể không tối ưu cho lập trình hệ thống cấp thấp hoặc đồ họa hiệu năng cao.

Tổng kết

  • FP là tính toán bằng cách đánh giá các biểu thức toán học.
  • Trụ cột của FP là Hàm thuần khiết, Tính bất biến và Hàm bậc cao.
  • Lambda Calculus cung cấp nền tảng lý thuyết với các khái niệm Lambda, Closure và Currying.
  • FP không thay thế OOP mà bổ sung cho nhau trong các ngôn ngữ đa mô hình hiện đại.
