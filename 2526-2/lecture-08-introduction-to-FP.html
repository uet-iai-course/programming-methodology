1.
Tổng quan về lập trình hàm

Từ OOP sang FP

Bài 5–7 ta xây dựng hệ thống bằng đối tượng, lớp, kế thừa.

  • OOP tổ chức code quanh trạng thái và hành vi của đối tượng.
  • FP tổ chức code quanh hàm và dữ liệu bất biến.
  • Hai mô hình không đối lập — hầu hết ngôn ngữ hiện đại kết hợp cả hai.

Nỗi đau của trạng thái


vector<int> data = {3, 1, 4};
void addBonus(vector<int>& v) { for(auto& x : v) x += 10; }
void normalize(vector<int>& v) { sort(v.begin(), v.end()); }

addBonus(data);   // data = {13, 11, 14}
normalize(data);  // data = {11, 13, 14} — thứ tự khác nếu gọi ngược!

Hai hàm cùng sửa data → kết quả phụ thuộc thứ tự gọi → khó debug.

FP giúp giảm điều này bằng cách ưu tiên dữ liệu bất biến và cô lập side effects.

Lập trình hàm là gì?

Định nghĩa

Lập trình hàm (Functional Programming - FP) là mô hình lập trình xây dựng chương trình bằng cách kết hợp các hàm và hạn chế thay đổi trạng thái.

  • Biểu thức thay vì trạng thái: Trong tư duy FP, ưu tiên biểu thức và hạn chế thay đổi trạng thái.
  • Minh bạch tham chiếu: Có thể thay lời gọi hàm bằng giá trị trả về mà không thay đổi hành vi chương trình.

FP khác tư duy mệnh lệnh ở đâu?

Đặc điểm Lập trình mệnh lệnh Lập trình hàm (FP)
Cơ chế chính Gán biến & thay đổi trạng thái Đánh giá biểu thức
Thứ tự thực hiện Rất quan trọng Ít phụ thuộc hơn khi hàm thuần
Side Effects Phổ biến Cố gắng cô lập
Hệ quả Cần test kỹ vì phụ thuộc trạng thái Dễ test, dễ suy luận hơn

Trạng thái và Bất biến

C++ (Cập nhật biến):


      int x=10;
      x = x + 5; // Trạng thái x thay đổi
      x = x * 2; // Giá trị cũ bị ghi đè

FP (Tạo giá trị mới):


      const int x = 10;
      const int y = x + 5; // x vẫn là 10
      const int z = y * 2; // y vẫn là 15
Trực quan: Mệnh lệnh giống như ghi đè lên bảng phấn. FP giống như chụp một loạt các bức ảnh, mỗi bức ảnh là một giá trị cố định.

Vì sao cần học FP?

  • Dễ suy luận: Không có biến ẩn thay đổi giá trị, mã nguồn trở nên minh bạch.
  • Dễ kiểm thử: Hàm thuần khiết luôn cho cùng kết quả với cùng đầu vào, không cần giả lập phức tạp.
  • Dễ tái sử dụng: Các hàm độc lập có thể lắp ghép như các khối Lego.
  • Hiện đại: Hầu hết các ngôn ngữ phổ biến (C++, Java, Python, JS) đều đang bổ sung các tính năng FP mạnh mẽ.

Bạn đã dùng FP rồi!

Những tính năng FP quen thuộc trong ngôn ngữ bạn đã biết:

Ngôn ngữ Tính năng FP bạn đã dùng
C++ Lambda [](int x){ return x*x; }, std::sort với comparator, Ranges (C++20)
Python map(), filter(), list comprehension, lambda
JavaScript const, arrow functions, .map(), .filter(), .reduce()

FP không chỉ có ở Haskell — nó đang ở trong code bạn viết hàng ngày.

2.
Các nguyên lý cốt lõi

4 nguyên tắc cốt lõi

  1. Hàm thuần khiết — cùng đầu vào → cùng đầu ra, không gây tác dụng phụ.
  2. Dữ liệu bất biến — không sửa, chỉ tạo mới.
  3. Hàm là giá trị — truyền vào, trả về, lưu trữ như dữ liệu.
  4. Tổ hợp hàm — ghép hàm nhỏ thành xử lý lớn: f(g(x)).

Các slide tiếp theo sẽ đi sâu từng nguyên tắc.

Hàm thuần khiết

Nguyên tắc vàng
  • Với cùng đầu vào, hàm luôn cho cùng đầu ra.
  • Không gây ra tác dụng phụ: Không gây thay đổi quan sát được ra bên ngoài.
✅ Pure:
square(x) = x * x
(Chỉ tính toán và trả về giá trị)
❌ Impure:
square(x) { print(x); return x*x; }
In màn hình, đọc biến global, gọi rand(), lấy thời gian...

Minh bạch tham chiếu:

Có thể thay lời gọi hàm bằng kết quả mà không đổi nghĩa chương trình.
Ví dụ: square(5) luôn thay được bằng 25.

Tính bất biến

  • Không sửa trực tiếp dữ liệu cũ: Một khi dữ liệu được tạo ra, nó không bao giờ thay đổi.
  • Tạo ra giá trị mới: Thay vì sửa trực tiếp, ta tạo ra giá trị mới phản ánh các thay đổi cần thiết.
Old: [1, 2, 3] --(add 4)--> New: [1, 2, 3, 4]

Mảng cũ giữ nguyên, tạo mảng mới chứa giá trị thay đổi.

Lưu ý cho giảng viên: Các ngôn ngữ FP hiện đại sử dụng Structural Sharing (chia sẻ cấu trúc) để tối ưu bộ nhớ thay vì sao chép toàn bộ dữ liệu. Nói miệng nếu có thời gian.

Hàm bậc cao

Ý chính
Trong FP, hàm được xem như một giá trị và có thể được truyền vào, trả về, hoặc lưu trữ như dữ liệu thông thường.
  • Hàm bậc cao: Nhận hàm khác làm tham số hoặc trả về một hàm mới.
  • Ví dụ quen thuộc: sort(v, cmp), filter(xs, pred), map(xs, f), reduce(xs, init, op).
  • Tổ hợp hàm: Ghép các bước nhỏ thành pipeline: filter → map → reduce.

Ví dụ: xử lý danh sách điểm

Bài toán: cho danh sách điểm, lấy điểm ≥ 60, quy về thang 10, rồi tính tổng. (mã giả theo phong cách FP, không phải cú pháp C++ cụ thể)

Mệnh lệnh (vòng lặp + biến)


vector<int> scores = {85, 42, 91, 67, 53, 78};
double total = 0;
for (int s : scores) {
    if (s >= 60) {        // lọc
        total += s / 10.0; // quy thang 10
    }
}
// total = 8.5 + 9.1 + 6.7 + 7.8 = 32.1

Pseudocode FP


vector<int> scores = {85, 42, 91, 67, 53, 78};

auto passed = filter(scores,
    [](int s) { return s >= 60; });

auto scaled = map(passed,
    [](int s) { return s / 10.0; });

double total = reduce(scaled, 0.0,
    [](double a, double b) { return a+b; });

Ít biến tạm, ít vòng lặp — ưu tiên ghép hàm lại với nhau.

Tổng hợp: FP pipeline

Cùng bài toán, nhìn qua lăng kính từng nguyên tắc:

Nguyên tắc Thể hiện trong ví dụ
Hàm thuần khiết Mỗi lambda chỉ tính toán, không đọc/ghi biến ngoài
Dữ liệu bất biến scores không bị sửa — mỗi bước tạo dữ liệu mới
Hàm bậc cao filter, map, reduce nhận lambda làm tham số
Tổ hợp hàm Pipeline: filter → map → reduce

Đệ quy, lambda, closure, currying ở phần tiếp theo không phải ý mới — chúng là công cụ để hiện thực tư duy FP.

3.
Đệ quy trong FP

Đệ quy

Trong FP, đệ quy là một cơ chế quan trọng để biểu diễn lặp mà không cần cập nhật biến đếm như trong vòng lặp truyền thống.

Lập trình mệnh lệnh: Vòng lặp


        int factorial(int n) {
            int result = 1;
            for(int i = 1; i <= n; i++)
                result *= i; // Cập nhật biến
            return result;
        }

Lập trình hàm: Đệ quy


        int factorial(int n) {
            // Không dùng biến đếm, không cập nhật
            if (n <= 1) return 1;
            return n * factorial(n - 1);
        }

Cấu trúc an toàn của đệ quy

Để tránh lỗi tràn ngăn xếp hoặc vòng lặp vô hạn, một hàm đệ quy luôn phải được xây dựng từ hai thành phần sống còn:

1. Điểm dừng

Là trường hợp đơn giản nhất mà hàm có thể trả về kết quả ngay lập tức không cần tính toán thêm.

  • Ngăn chặn đệ quy vô hạn.
  • Thường nằm ở đầu hàm.

        if (n <= 1) return 1;
2. Bước đệ quy

Là phần logic chia nhỏ bài toán lớn thành các bài toán con tương tự nhưng có kích thước nhỏ hơn.

  • Gọi lại chính nó.
  • Tiến dần về phía điểm dừng.

        return n * factorial(n - 1);
⚠️ Cảnh báo: Nếu thiếu Điểm dừng hoặc Bước đệ quy không tiến về điểm dừng, chương trình sẽ gây treo hệ thống hoặc cạn kiệt bộ nhớ Stack.

Tối ưu hóa đệ quy (nâng cao)

Đệ quy đuôi

Là trường hợp lời gọi đệ quy là hành động cuối cùng của hàm. Trình biên dịch có thể tái sử dụng vùng nhớ Stack, giúp hiệu năng tương đương vòng lặp.


// Biến tích lũy → lời gọi đệ quy là lệnh cuối
int factorial(int n, int acc = 1) {
    if (n <= 1) return acc;
    return factorial(n - 1, n * acc); // Tail call
}

⚠️ C++ không đảm bảo TCO theo chuẩn — phụ thuộc compiler (GCC/Clang thường hỗ trợ, MSVC không). Haskell, Scheme đảm bảo TCO.

4.
Lambda, Closure và Currying

Lambda: hàm ẩn danh

Lambda là hàm không cần đặt tên — viết ngay tại chỗ dùng.


// Hàm có tên
int square(int x) { return x * x; }

// Lambda — cùng logic, không cần tên
auto square = [](int x) { return x * x; };

// Dùng ngay mà không gán tên
std::sort(v.begin(), v.end(),
    [](int a, int b) { return a > b; });

Cú pháp C++: [capture](params) { body }

Bao đóng (Closure)

Ý chính

Closure là lambda + các biến bên ngoài mà nó "bắt" (capture) lại.

Hàm thông thường


bool checker(int value, int threshold) {
    return value > threshold;
}
checker(120, 100); // phải truyền threshold mỗi lần
checker(50, 100);

Closure (Lambda Capture)


int threshold = 100;
auto isOver = [threshold](int value) {
    return value > threshold;
}; // "Gói" threshold vào hàm
isOver(120); // true — chỉ cần 1 tham số
Closure = Hàm + dữ liệu đã capture

Function pointer chỉ trỏ đến mã; closure mang theo cả dữ liệu đã capture.
Tại sao không truyền tham số luôn? Vì API như filter, sort chỉ nhận hàm 1 tham số — closure giúp "gói" dữ liệu thêm vào.

Currying và Partial Application

Currying: biến hàm nhiều tham số thành chuỗi hàm, mỗi hàm nhận 1 tham số.

Hàm thông thường


int add(int x, int y) {
    return x + y;
}
int res = add(5, 10); // 15

Hàm đã Curried


auto curried_add = [](int x) {
    return [x](int y) { return x + y; };
};
auto add5 = curried_add(5); // partial!
int res = add5(10);         // 15
Currying = cách biến đổi hàm (nhiều tham số → chuỗi hàm 1 tham số).
Partial Application = cách dùng hàm đã curried để cố định bớt tham số.
curried_add(5) trả về hàm "cộng thêm 5" — đó là partial application.

Gốc lý thuyết: Phép tính Lambda

Mọi khái niệm trên đều bắt nguồn từ Lambda Calculus (Alonzo Church, 1936).

  • $\lambda x.M$ — định nghĩa hàm ẩn danh (tương đương lambda trong code).
  • $E_1\ E_2$ — áp dụng hàm lên đối số.

$\lambda x.\ x + y$

$x$ = biến ràng buộc (tham số), $y$ = biến tự do (cần capture → closure!)

Lambda Calculus chứng minh: chỉ cần hàm là đủ để biểu diễn mọi tính toán.

5.
Khi nào FP mạnh, khi nào FP khó

FP mạnh ở đâu?

  • Dễ suy luận: Do tính minh bạch tham chiếu, ta có thể hiểu hàm mà không cần biết trạng thái toàn cục của hệ thống.
  • Dễ kiểm thử: Các hàm thuần khiết độc lập hoàn toàn, không cần giả lập môi trường phức tạp.
  • Tính tái sử dụng: Hàm bậc cao và kết hợp hàm tạo ra các thành phần cực kỳ linh hoạt.
  • Song song hóa: Tính bất biến giúp giảm mạnh nguy cơ xung đột dữ liệu giữa các luồng.

FP khó ở đâu?

  • Hiệu năng: Việc sao chép dữ liệu để đảm bảo bất biến có thể gây tốn bộ nhớ — tuy nhiên các ngôn ngữ FP hiện đại dùng Structural Sharing để giảm thiểu chi phí này.
  • Độ dốc học tập: Yêu cầu lập trình viên từ bỏ các thói quen mệnh lệnh (vòng lặp, gán giá trị) để chuyển sang tư duy hàm.
  • Khi nào dùng: FP cực kỳ hiệu quả cho xử lý dữ liệu, trình biên dịch, hệ thống phân tán; nhưng có thể không tối ưu cho lập trình hệ thống cấp thấp hoặc đồ họa hiệu năng cao.

Tổng kết

  1. Ưu tiên hàm thuần — cùng input, cùng output.
  2. Ưu tiên dữ liệu bất biến — không sửa, chỉ tạo mới.
  3. Mô tả xử lý như chuỗi biến đổi dữ liệu — filter → map → reduce.

FP không thay thế OOP — chúng bổ sung cho nhau trong ngôn ngữ hiện đại.
