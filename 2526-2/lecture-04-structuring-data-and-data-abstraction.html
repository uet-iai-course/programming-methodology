Tại sao cần kiểu dữ liệu?

  • Phần cứng chỉ thấy bit.
  • Lập trình viên cần khái niệm gần bài toán hơn.
  • Kiểu dữ liệu gắn bit với ý nghĩa.

Tại sao cần kiểu dữ liệu?

  • Thiết kế: mô hình hoá bài toán bằng kiểu — SinhVien, KhoaHoc, DiemThi — thay vì chỉ dùng int hay string thuần.
  • Kiểm tra: trình biên dịch bắt lỗi gán nhầm kiểu trước khi chạy.
  • Cài đặt: hỗ trợ cấp phát và tối ưu bộ nhớ.

Kiểu dữ liệu là gì?

Định nghĩa
Kiểu dữ liệu = tập giá trị + cách biểu diễn + các thao tác.
  • Đồng nhất: cùng cấu trúc hoặc cùng cách dùng.
  • Biểu diễn hiệu quả: lưu được trong bộ nhớ hữu hạn.
  • Thao tác hiệu quả: tính toán được trên biểu diễn đó.

Ba tính chất của giá trị

Tính chất Ý nghĩa
Denotable Giá trị có thể đặt tên (khai báo, tham số, …)
Expressible Giá trị có thể là kết quả biểu thức (không cần tên)
Storable Giá trị có thể gán vào biến hoặc truyền như tham số

Câu hỏi: hàm có thỏa cả 3 tính chất? — tùy ngôn ngữ.

Ba tính chất của giá trị

Python — hàm thỏa cả 3:


# Denotable — có thể đặt tên
def double(x):
    return x * 2

# Expressible — tồn tại như biểu thức, không cần tên
# lambda TẠO RA hàm tại chỗ và dùng luôn
print((lambda x: x * 2)(5))   # 10
#     |_______________|
#     biểu thức → hàm, không có tên

# Storable — gán vào biến, bỏ vào danh sách
f = double
ops = [double, abs, len]

C — hàm chỉ là denotable:


// Denotable — hàm phải có tên
int double(int x) { return x * 2; }

// KHÔNG expressible — không thể tạo hàm tại chỗ
// Muốn dùng hàm, phải khai báo có tên trước

// Storable chỉ qua con trỏ hàm (không tự nhiên)
int (*f)(int) = double;  // lưu địa chỉ, không phải giá trị

→ Hàm trong C không phải giá trị hạng nhất (first-class value).

Hệ thống kiểu (Type System)

Thành phần của hệ thống kiểu
  • Kiểu tiền định.
  • Cách tạo kiểu mới.
  • Quy tắc tương đương.
  • Quy tắc tương thích.
  • Quy tắc suy diễn kiểu.
  • Kiểm tra tĩnh hay động.

Hệ thống kiểu an toàn nếu lỗi kiểu không thể lọt qua mà không bị phát hiện.

Hệ thống kiểu (Type System)

Ví dụ — C++ minh họa từng thành phần:


// Kiểu tiền định
int x = 5;
bool flag = true;

// Kiểu mới do người dùng tạo
struct Point { int x, y; };
Point p = {1, 2};

// Tương thích: int → double (coercion ngầm)
double d = x;           // hợp lệ — int tương thích double

// Suy diễn kiểu (C++11)
std::map<std::string, std::vector<int>> m;
auto it = m.begin();   // kiểu thật: std::map<...>::iterator — quá dài!

// Kiểm tra tĩnh — lỗi xảy ra trong lúc biên dịch
std::string s = x;      // LỖI: int không tương thích std::string
p = "hello";            // LỖI: const char* không tương thích Point

Kiểm tra kiểu: Tĩnh vs Động

Java — static: lỗi bắt tại compile-time 


String name = "Alice";

// Trình biên dịch báo lỗi NGAY — không chạy được
int x = name;  // LỖI: incompatible types

System.out.println(x);  // không bao giờ chạy đến đây

✓ Lỗi bị chặn trước khi deploy

Python — dynamic: lỗi chỉ xảy ra tại runtime 


name = "Alice"

# Không có lỗi... cho đến khi chạy đến đây
if some_rare_condition:
    x = name + 5  # TypeError — nhưng chỉ khi
                  # nhánh này được kích hoạt!

✗ Lỗi có thể lọt qua test, có thể chỉ xuất hiện trên production

→ Đây cũng là lý do TypeScript ra đời: bổ sung static typing cho JavaScript.

Phân loại độ an toàn kiểu

Ví dụ — tại sao C bị xếp không an toàn:

Union: đọc sai trường


union Data { int i; float f; };

union Data d;
d.f = 3.14f;       // ghi vào trường float

// Đọc ra trường int — KHÔNG bị báo lỗi
printf("%d\n", d.i);
// → in ra số ngẫu nhiên vô nghĩa

Ép kiểu con trỏ tùy tiện


int x = 42;

// Ép kiểu tùy tiện — trình biên dịch không cản
float *p = (float *)&x;

// Đọc bits của int như float
printf("%f\n", *p);
// → hành vi không xác định, kết quả vô nghĩa

→ Cả hai lỗi trên đều hợp lệ về cú pháp, trình biên dịch không cảnh báo — lỗi chỉ lộ ra lúc chạy hoặc không bao giờ.

Kiểu vô hướng (Scalar Types)

Giá trị không ghép từ giá trị khác.

Kiểu Giá trị Hệ quả thực tế
Boolean true, false
Character Mã ký tự ASCII (1 byte) hoặc Unicode (2–4 bytes)
Integer Tập con hữu hạn của ℤ Hữu hạn → có thể tràn số (overflow)
Real Tập con hữu hạn của ℚ Xấp xỉ → 0.1 + 0.2 ≠ 0.3
Unit / Void Một giá trị () Biểu diễn "không có kết quả"
Lưu ý: void là kiểu có đúng một giá trị, không phải tập rỗng.

Kiểu liệt kê (Enumeration)

Tập hữu hạn các hằng số có tên — thay cho số nguyên thô.

  • Dễ đọc, dễ bảo trì hơn magic number.
  • Là kiểu có thứ tự — có thể so sánh, lặp.
  • C: enum vẫn là int — không an toàn kiểu.
    C++ enum class, Python Enum: mỗi enum là kiểu riêng biệt.

Kiểu liệt kê — C++ enum class


// ❌ Không dùng enum — magic number, không an toàn kiểu
void capNhat(int trangThai) {
    if (trangThai == 2)  // 2 là gì? Ai nhớ?
        guiThongBao();
}
capNhat(999);            // Hợp lệ! Trình biên dịch không cản

// ✅ Dùng enum class — rõ ràng, an toàn
enum class TrangThai { ChoXuLy, DangGiao, DaGiao, DaHuy };

void capNhat(TrangThai t) {
    if (t == TrangThai::DaGiao)
        guiThongBao();
}
capNhat(999);            // LỖI biên dịch — an toàn!
📖 Tự học

Kiểu liệt kê — Python Enum


from enum import Enum

class MauDen(Enum):
    DO   = 1
    VANG = 2
    XANH = 3

den = MauDen.DO

# Rõ nghĩa hơn so với dùng số nguyên thô
if den == MauDen.DO:
    print("Dừng lại")       # thay vì: if den == 1

# Enum hỗ trợ lặp và so sánh thứ tự
for mau in MauDen:
    print(mau.name, mau.value)

Python Enum còn hỗ trợ IntEnum, Flag, auto() — linh hoạt hơn C.

Kiểu khoảng (Interval)

Tập con liên tục của một kiểu cơ sở — ràng buộc miền ghi thẳng vào kiểu.


type DiemThi    = 0..100;       -- kiểu cơ sở: Integer
type Thang      = 1..12;        -- kiểu cơ sở: Integer
type GioLamViec = 9..17;        -- kiểu cơ sở: Integer
  • Dùng được như kiểu cơ sở — nhưng không ngược lại.
  • Lỗi vượt cận thường phát hiện động (lúc chạy).
  • Ràng buộc nằm trong kiểu → không thể quên kiểm tra.
📖 Tự học

Kiểu khoảng (Interval)

Tại sao interval type có giá trị — đối chiếu Ada vs C++:


-- Ada: ràng buộc nằm trong kiểu, kiểm tra tự động
subtype DiemThi    is Integer range 0..100;
subtype GioLamViec is Integer range 9..17;

diem : DiemThi    := 150;  -- Constraint_Error tự động!
gio  : GioLamViec := 25;   -- Constraint_Error tự động!
          

// C++: không có interval type — developer tự lo
int diem = 150;   // hợp lệ, không ai cản
int gio  = 25;    // hợp lệ, không ai cản

// Phải tự nhớ kiểm tra — dễ bỏ sót
assert(diem >= 0 && diem <= 100);
assert(gio  >= 9 && gio  <= 17);

→ Interval type chuyển ràng buộc từ "developer tự nhớ" sang "hệ thống kiểu tự kiểm tra".

Bản ghi (Record)

Tập hữu hạn các trường có tên — mỗi trường có kiểu riêng.


struct SinhVien {
    int  maSV;           // 4 bytes
    char hoTen[32];      // 32 bytes
    float diemTB;        // 4 bytes
};

SinhVien sv = {20210001, "Nguyen Van A", 3.5f};
std::cout << sv.hoTen << ": " << sv.diemTB;
  • Truy cập trường qua offset hằng số — O(1), biết tại compile-time.
  • Căn biên (alignment): CPU đọc hiệu quả nhất khi địa chỉ chia hết cho kích thước kiểu → trình biên dịch tự chèn padding.

Bản ghi — Offset hằng số

Mỗi trường có một offset cố định (byte) tính từ đầu struct — trình biên dịch biết con số này tại compile-time. 


struct SinhVien {
    int   maSV;      // offset  0  (4 bytes)
    char  hoTen[32]; // offset  4  (32 bytes)
    float diemTB;    // offset 36  (4 bytes)
};

Khi bạn viết sv.diemTB = 3.5f;, trình biên dịch dịch thành:


// Mã nguồn:
sv.diemTB = 3.5f;

// Trình biên dịch tạo ra (tương đương):
*( float* )( (char*)&sv + 36 ) = 3.5f;
//                         ↑ con số này đã biết từ compile-time

→ Truy cập trường chỉ là 1 phép cộng + 1 lần đọc bộ nhớ — O(1), không phụ thuộc vào số trường hay kích thước struct.

📖 Tự học

Bản ghi — Vấn đề căn biên (Alignment)

int (4 bytes) cần địa chỉ chia hết cho 4. Nếu đặt sau char, compiler phải chèn padding: 


struct A {
    char  c;    // offset 0 — 1 byte
                // [pad][pad][pad] — 3 byte rỗng, đẩy i xuống offset 4
    int   i;    // offset 4 — 4 bytes (4 chia hết cho 4 ✓)
    char  d;    // offset 8 — 1 byte
                // [pad][pad][pad] — 3 byte rỗng, struct size phải chia hết cho 4
};
// Layout: [c][...][...][...][i ][i ][i ][i ][d][...][...][...]
// sizeof(A) = 12,  không phải 6!

struct B {       // sắp xếp lại: lớn trước, nhỏ sau
    int   i;    // offset 0 — 4 bytes
    char  c;    // offset 4 — 1 byte
    char  d;    // offset 5 — 1 byte
                // [pad][pad] — chỉ 2 byte padding cuối
};
// Layout: [i ][i ][i ][i ][c][d][..][..]
// sizeof(B) = 8  — tiết kiệm hơn A!

→ Nên khai báo trường từ lớn đến nhỏ để giảm padding.

Mảng (Array)

Các phần tử cùng kiểu, truy cập bằng chỉ số — O(1).


// Mảng 1 chiều
int diem[30];             // 30 phần tử int, chỉ số 0..29
diem[0] = 95;

// Mảng 2 chiều (ma trận)
double maTran[3][4];      // 3 hàng, 4 cột
maTran[1][2] = 3.14;

// Mảng ký tự — chuỗi trong C
char ten[32] = "Nguyen Van A";
  • Chỉ số bắt đầu từ 0 trong C/C++/Java/Python.
  • Kích thước cố định — muốn động dùng std::vector.

Mảng 2 chiều — Row-major order

Bộ nhớ máy tính là 1 chiều (dãy byte liên tiếp). Khi lưu mảng 2 chiều, cần chọn thứ tự: C/C++ dùng row-major — lưu hết hàng này rồi mới sang hàng sau.

Ma trận int A[2][3]:

A[0][0] A[0][1] A[0][2]
A[1][0] A[1][1] A[1][2]

Trong bộ nhớ (địa chỉ tăng dần →):

A[0][0] A[0][1] A[0][2] A[1][0] A[1][1] A[1][2]
← hàng 0 → ← hàng 1 →

Offset của A[i][j] = (i × 3 + j) × sizeof(int)

⚠️ Hệ quả thực tế: duyệt theo hàng (A[i][j]) nhanh hơn theo cột (A[j][i]) vì phần tử liền kề nằm liền kề trong bộ nhớ → cache thân thiện hơn.

Hình dạng mảng (Array Shape)

Hình dạng = số chiều + miền chỉ số mỗi chiều.


// Tĩnh — hình dạng biết tại compile-time, truy cập nhanh nhất
int a[10];
double maTran[3][4];

// Cố định khi khai báo — biết lúc chạy, không thay đổi sau đó
int n;
std::cin >> n;
int b[n];              // C99 VLA — kích thước từ runtime, stack

// Động hoàn toàn — có thể thay đổi kích thước bất kỳ lúc nào
std::vector<int> v;
v.push_back(1);        // tự cấp phát lại khi đầy — heap
v.push_back(2);

Dope Vector

Mảng tĩnh — hình dạng biết lúc compile:


double a[3][4];
// a[i][j] → trình biên dịch viết thẳng:
// base + i*32 + j*8  (hằng số trong mã máy)

Mảng động — hình dạng chỉ biết lúc chạy:


int n, m;
std::cin >> n >> m;
// Lúc compile chưa biết n, m
// → phải lưu metadata ở đâu đó khi chạy

Dope vector

base địa chỉ khối dữ liệu
ndim số chiều
lb[k] biên dưới chiều k
stride[k] số byte / bước chiều k

Cấu trúc này được tạo lúc chạy,
lưu trong stack frame của hàm.

Dope Vector — Ví dụ cụ thể

float b[n][m] khai báo lúc chạy với n=3, m=4:

Dope vector của b

base →  [khối 48 byte trên heap]
ndim = 2
lb = [0, 0]
stride = [16, 4]  (byte)

stride[0] = m × sizeof(float) = 4×4 = 16
stride[1] = sizeof(float) = 4

Truy cập b[i][j]:

addr = base
       + i × stride[0]
       + j × stride[1]
// b[2][3] =
addr = base + 2×16 + 3×4
     = base + 44

✅ Vẫn là O(1) — chỉ đọc stride từ bộ nhớ thay vì dùng hằng số compile-time.

Hợp có gắn thẻ (Tagged Union)

Mỗi giá trị kèm thẻ chỉ biến thể hợp lệ — truy cập sai biến thể báo lỗi.


#include <variant>
#include <string>

// C++17: std::variant — tagged union an toàn kiểu
using GiaTri = std::variant<int, double, std::string>;

GiaTri v = 42;              // biến thể int
v = 3.14;                   // biến thể double
v = std::string("hello");   // biến thể string

// Truy cập — tự động chọn đúng biến thể
std::visit([](auto val) {
    std::cout << val << "\n";
}, v);

// Truy cập sai biến thể → throw std::bad_variant_access
int n = std::get<int>(v);   // LỖI runtime: v đang là string!

Hợp có gắn thẻ — Python


# Python 3.10+: match/case — tương đương tagged union
def xu_ly(gia_tri: int | float | str) -> str:
    match gia_tri:
        case int(n):
            return f"Số nguyên: {n}"
        case float(f):
            return f"Số thực: {f:.2f}"
        case str(s):
            return f"Chuỗi: '{s}'"

print(xu_ly(42))       # Số nguyên: 42
print(xu_ly(3.14))     # Số thực: 3.14
print(xu_ly("hello"))  # Chuỗi: 'hello'
  • Truy cập sai biến thể → báo lỗi lúc chạy.
  • Đây là kiểu tổng (sum type) — enum là trường hợp đặc biệt.

Con trỏ (Pointer)

Con trỏ là địa chỉ của đối tượng kiểu T.


int* p = malloc(sizeof(int));
*p = 33;           // ghi qua dereference

float r = 3.14;
float* q = &r;     // con trỏ vào stack
r = *q + 1;        // đọc qua dereference

Con trỏ — Hai mối nguy hiểm chính


// ⚠ Tham chiếu treo (dangling reference)
int* p;
{
    int x = 42;
    p = &x;
}   // x bị hủy ở đây!
*p = 10;   // hành vi không xác định — p trỏ vào vùng đã giải phóng

// ⚠ Số học con trỏ (pointer arithmetic) — dễ vượt biên mảng
int arr[5] = {1, 2, 3, 4, 5};
int* q = arr;
q += 10;   // q trỏ ra ngoài mảng
*q = 99;   // hành vi không xác định — có thể ghi đè dữ liệu khác!

→ C++ hiện đại dùng std::unique_ptr / std::shared_ptr để tránh tham chiếu treo; dùng std::vector thay mảng thô để tránh vượt biên.

Kiểu đệ quy (Recursive Types)

Giá trị có thể chứa tham chiếu tới chính kiểu đó — nền tảng của linked list, tree.


// C++: kiểu đệ quy qua con trỏ
struct Node {
    int   val;
    Node* next;   // con trỏ đệ quy — cùng kiểu!
};

// Xây dựng danh sách [1 → 2 → 3 → null]
Node* l = new Node{1, new Node{2, new Node{3, nullptr}}};

// Duyệt danh sách
for (Node* cur = l; cur != nullptr; cur = cur->next)
    std::cout << cur->val << " ";
  • Các node trên heap, nối nhau qua con trỏ.
  • C++: phải tự giải phóng (delete) hoặc dùng unique_ptr.

Tương thích kiểu

Ba câu hỏi cốt lõi

① Tương đương kiểu

Khi nào T ≡ S?

  • Theo tên: khai báo khác → kiểu khác
  • Theo cấu trúc: hình dạng giống → tương đương

② Tương thích kiểu

Khi nào T dùng được ở chỗ cần S?

  • T ≡ S  hoặc  T ⊆ S
  • Có chuyển đổi (chuẩn / tự định nghĩa)
  • Cùng tập thao tác (duck typing)

③ Chuyển đổi kiểu

Ai thực hiện, ai chịu trách nhiệm?

  • Coercion: ngôn ngữ tự chèn (ngầm)
  • Cast: lập trình viên viết tường minh

Nhiều ngôn ngữ pha trộn cả ba — hiểu rõ giúp đọc và viết mã chính xác hơn.

Tương đương tên
(Name Equivalence)

Mỗi khai báo struct / type tạo ra một kiểu riêng biệt — dù cấu trúc bên trong giống hệt.


struct Room  { int value; };   // số phòng
struct Price { int value; };   // giá tiền (VND)

Room  r{101};
Price p{250000};

r = p;   // ❌ lỗi biên dịch: cannot convert 'Price' to 'Room'
         //   dù cả hai đều chỉ có một trường int
✅ Lợi ích thiết kế: trình biên dịch tự phát hiện khi gán nhầm số phòng vào giá tiền — lỗi logic bị bắt ngay ở compile-time.

Tương đương cấu trúc
(Structural Equivalence)

Hai kiểu tương đương nếu có cùng cấu trúc khi mở rộng hoàn toàn.

C — typedef là alias thuần túy:


typedef int Meters;
typedef int Pixels;

Meters  m  = 100;
Pixels  px = m;   // ✅ hợp lệ!
// C không phân biệt Meters vs Pixels
// — cả hai đều mở rộng thành int

C++ — struct tạo kiểu mới: 


struct Meters { int v; };
struct Pixels { int v; };

Meters m{100};
Pixels px = m;   // ❌ lỗi biên dịch
// Name equivalence: Meters ≠ Pixels

⚠ Kiểu đệ quy (struct Node { Node* next; }) không thể dùng structural equivalence — mở rộng sẽ không dừng.

Ngôn ngữ dùng quy tắc nào?

Ngôn ngữ Struct / Record Array Type alias
C Tên Cấu trúc Cấu trúc (typedef)
C++ Tên Cấu trúc Tên (using)
Java Tên Cấu trúc Tên
TypeScript Cấu trúc Cấu trúc Cấu trúc
Python Kiểm tra lúc chạy (duck typing) — không áp dụng quy tắc tĩnh

Hầu hết ngôn ngữ pha trộn: name equivalence cho struct, structural cho array.

Tương thích kiểu
(Type Compatibility)

Tương thích: giá trị kiểu T dùng được ở nơi cần kiểu S.

① T ≡ S  —  cùng kiểu


int x = 5;
int y = x;   // ✅ hiển nhiên

② T ⊆ S  —  kiểu con


subtype Score is Integer range 0..100;
Score   s := 85;
Integer i := s;  -- ✅ Score ⊆ Integer

③ Chuyển đổi chuẩn


int    i = 42;
long   l = i;   // ✅ int → long
double d = i;   // ✅ int → double

④ Chuyển đổi tự định nghĩa


struct Celsius {
  double val;
  operator double() { return val; }
};
Celsius c{36.6};
double  t = c;  // ✅ gọi operator double()

Coercion và Cast

Cả hai đều chuyển đổi giá trị — khác ở ai quyết định và ai chịu trách nhiệm.

Coercion — ngầm định


double d = 3 + 2.5;
// Trình biên dịch tự chèn:
//   (double)3 + 2.5  →  5.5  ✅

// ⚠ Bẫy thường gặp:
int x = 5, y = 2;
double r = x / y;
// → 2.0, không phải 2.5!
// Phép chia int xảy ra TRƯỚC coercion

Cast — tường minh


int x = 5, y = 2;
double r = (double)x / y;  // → 2.5 ✅

// ⚠ Cast không kiểm tra giá trị:
double pi = 3.14159;
int n = (int)pi;     // → 3  (mất 0.14159)

long big = 3000000000L;
int  sm  = (int)big; // → tràn số, kết quả sai

💡 Ưu tiên cast tường minh: ý định rõ ràng trong mã, dễ review và debug hơn.

Tương thích cấu trúc tĩnh

Kiểm tra ở compile-time rằng kiểu có đủ trường / phương thức cần dùng.


// TypeScript: structural typing — kiểm tra ở compile-time
function printArea(shape: { width: number; height: number }): void {
    console.log(shape.width * shape.height);
}

printArea({ width: 5, height: 3 });               // ✅ đủ trường
printArea({ width: 5, height: 3, color: "red" }); // ✅ thêm trường cũng được
printArea({ width: 5 });                          // ❌ lỗi compile: thiếu height
So sánh với name equivalence (Java/C++)
TypeScript không cần khai báo implements — chỉ cần có đủ trường là được. Java/C++ yêu cầu khai báo quan hệ kiểu tường minh.

Duck Typing ⚠ ngoài giáo trình

Tương thích cấu trúc kiểm tra lúc chạy: có thao tác cần thiết thì dùng được.


def make_sound(animal):

✅ Linh hoạt tối đa — không cần khai báo quan hệ kiểu
⚠ Lỗi xuất hiện muộn — chỉ bắt được lúc chạy, không phải lúc biên dịch

Ad-hoc — Overloading

Cùng tên hàm, trình biên dịch chọn phiên bản dựa trên kiểu đối số.

Function overloading:


void print(int x)    { cout << x; }
void print(double x) { cout << x; }
void print(string x) { cout << x; }

print(42);       // → print(int)
print(3.14);     // → print(double)
print("hello");  // → print(string)

Operator overloading:


// + cho int:    cộng số nguyên
// + cho double: cộng số thực
// + cho string: nối chuỗi
int    r1 = 1   + 2;     // → 3
double r2 = 1.0 + 2.0;   // → 3.0
string r3 = "ab" + "cd"; // → "abcd"
// Ba phép toán KHÁC NHAU, cùng ký hiệu +

⚠ Việc chọn hàm xảy ra ở compile-time — không có chi phí lúc chạy.

📖 Tự học

Overloading vs Coercion

Cùng biểu thức 1 + 2.0 — hai ngôn ngữ xử lý khác nhau hoàn toàn:

C++ — Overloading + Coercion


double r = 1 + 2.0;
// Bước 1 (coercion): 1 → 1.0
// Bước 2 (overload): chọn +(double, double)
// → r = 3.0

C++ dùng cả hai: coercion chuyển kiểu, sau đó overloading chọn hàm phù hợp.

Ada — Chỉ Overloading, không Coercion


-- Ada không tự chuyển đổi kiểu
X : Integer := 1;
Y : Float   := 2.0;
Z : Float   := X + Y;  -- ❌ lỗi compile!

-- Phải viết tường minh:
Z := Float(X) + Y;     -- ✅

Ada chỉ dùng overloading — không có coercion ngầm → an toàn hơn.

Parametric — C++ Templates

Viết một lần với <typename T>. Trình biên dịch sinh mã riêng cho mỗi kiểu được dùng.


template <typename T>
T max(T a, T b) {
    return a > b ? a : b;
}

int    m1 = max(3, 7);          // → 7
double m2 = max(1.5, 2.3);     // → 2.3
string m3 = max("cat","dog");  // → "dog"
✅ Hiệu năng tối đa — mã được tối ưu riêng cho từng kiểu, không có chi phí runtime
⚠ Code bloat — mỗi kiểu sinh thêm một bản mã máy (max<int>, max<double>, max<string>…)
📌 Python def max(a, b) cũng parametric — nhưng kiểm tra lúc chạy, không phải compile-time

Subtype — Đa hình kiểu con

Kiểu con dùng được ở mọi nơi cần kiểu cha — hàm nào chạy được quyết định lúc chạy.

C++ — virtual:


struct Animal {
    virtual void speak() = 0;

struct Dog : Animal {

struct Cat : Animal {
    void speak() { cout << "Meo!\n"; }

void makeSound(Animal* a) { a->speak(); }

Suy diễn kiểu (Type Inference)

Trình biên dịch đọc code và tự giải ra kiểu — như giải bài toán logic từ các manh mối.

Ví dụ — trình biên dịch suy ra từng bước: 


auto x = 5;           // 5 là int       → x : int
auto y = x + 1.5;     // int + double   → y : double
auto z = y > 3.0;     // double > double→ z : bool

Template — T được "giải" từ đối số: 


template <typename T>
T max(T a, T b) { return a > b ? a : b; }

max(3, 7);        // đối số là int   → T = int
max(1.5, 2.3);    // đối số là double→ T = double
max("a", "b");    // đối số là string→ T = string
// Lập trình viên không cần viết max<int>(3, 7)

Kiểu cụ thể

Có đủ ràng buộc → trình biên dịch suy ra một kiểu duy nhất.

n + 1  →  n : int

Biến kiểu tự do

Không có ràng buộc → T có thể là bất kỳ kiểu nào → cùng một đoạn mã chạy cho tất cả.

id(x){return x}  →  T → T

📖 Tự học

Suy diễn kiểu

Thuật toán Unification

Slide trước cho thấy kết quả suy diễn. Câu hỏi: trình biên dịch làm thế nào để tìm ra y : double từ auto y = x + 1.5?

3 bước

  1. Gán biến kiểu
    mỗi biểu thức → τ?
  2. Sinh ràng buộc
    từ ngữ nghĩa phép toán → phương trình
  3. Giải (Unify)
    tìm kiểu thỏa tất cả phương trình

Trace: auto y = x + 1.5  (biết trước: x : int)

Bước Kết quả
① Gán biến kiểu x : int (đã biết),  1.5 : double,  x+1.5 : τ₁,  y : τ₂
② Sinh ràng buộc + với (int, double) trả về double  →  τ₁ = double
phép gán: τ₂ = τ₁
③ Giải τ₁ = double,  τ₂ = double  →  y : double ✅   ← kết quả đúng như slide trước

Cơ chế này chạy tự động cho toàn bộ chương trình — lập trình viên chỉ cần viết auto, trình biên dịch làm phần còn lại.

Vấn đề — struct không che giấu biểu diễn

❌ struct — mọi thứ đều công khai

struct Stack {
    int data[100];
    int top = 0;
};

Stack s;
s.top = -5;          // hợp lệ!
s.data[99] = 42;     // hợp lệ!

// Client "biết" biểu diễn
// → phụ thuộc vào chi tiết cài đặt
✅ class — ẩn biểu diễn

class Stack {
    int data[100]; // private (mặc định)
    int top = 0;
public:
    void push(int x) { data[top++] = x; }
    int  peek()      { return data[top-1]; }
    bool empty()     { return top == 0; }
};

Stack s;
s.push(42);        // ✓ thao tác hợp lệ
s.top = -5;        // ✗ lỗi biên dịch!

ADT = cho phép định nghĩa kiểu có cơ chế che giấu tương tự int, bool.

5 thành phần của ADT


class Stack {              // ① Tên kiểu
    int data[100];         // ② Biểu diễn bên trong
    int top = 0;           //    (ẩn với bên ngoài)
public:
    // ③ Chữ ký (signature) — giao diện công khai
    void push(int x);
    int  peek() const;
    void pop();
    bool empty() const;

    // ④ Cài đặt thao tác
    void push(int x)      { data[top++] = x; }
    int  peek() const     { return data[top-1]; }
    void pop()            { --top; }
    bool empty() const    { return top == 0; }
};
// ⑤ Vỏ bảo mật: private/public tách giao diện & cài đặt
① Tên kiểu
Stack — kiểu dữ liệu mới
② Biểu diễn
data[], top — ẩn hoàn toàn
③ Chữ ký
Tên + kiểu tham số & trả về
④ Cài đặt
Thân hàm — ẩn với bên ngoài
⑤ Vỏ bảo mật
private, public

Phân loại thao tác trong ADT

Loại Mô tả Ví dụ — Stack
Constructors Tạo giá trị mới kiểu T Stack() — tạo stack rỗng
push(x) — tạo stack từ stack + x
Transformers Biến đổi T → T mới pop() — trả về stack không có đỉnh
Observers Quan sát T → kiểu khác peek() → int
empty() → bool
Quy tắc
Không có constructor → không tạo được giá trị ADT.
Không có observer → không lấy được thông tin ra ngoài.

Độc lập biểu diễn

Hai cài đặt khác nhau, cùng giao diện (push / pop / peek / empty):

Cài đặt 1 — mảng tĩnh

class Stack {
    int data[100];
    int top = 0;
public:
    void push(int x)   { data[top++] = x; }
    int  peek() const  { return data[top-1]; }
    void pop()         { --top; }
    bool empty() const { return top == 0; }
};
Cài đặt 2 — vector động

class Stack {
    vector<int> data;
public:
    void push(int x)   { data.push_back(x); }
    int  peek() const  { return data.back(); }
    void pop()         { data.pop_back(); }
    bool empty() const { return data.empty(); }
};

Mã client — giống hệt cho cả hai cài đặt 

Stack s;

s.pop();
cout << s.peek();  // 20

Client chỉ thấy hành vi qua giao diện —
không thấy data[] hay vector.

Muốn đổi cài đặt? Chỉ cần compile lại.
Mã client không cần sửa gì.

Module

ADT đóng gói một kiểu. Module đóng gói nhiều kiểu & hàm liên quan.

📄 stack.py — module

# stack.py
_data = []  # "private" (quy ước _)

def push(x): _data.append(x)
def pop():   return _data.pop()
def peek():  return _data[-1]
def empty(): return len(_data) == 0
📄 main.py — client

import stack

stack.push(10)
stack.push(20)
print(stack.peek())   # 20
stack.pop()
print(stack.empty())  # False

# stack._data  ← không nên truy cập
C++: module = stack.h (chữ ký — public) + stack.cpp (cài đặt — private). Đổi .cpp → không cần recompile client (biên dịch riêng biệt).

Module tổng quát (Generic Module)

Module nhận tham số kiểu — viết một lần, dùng cho mọi kiểu:

C++ — Templates

template <typename T>
class Stack {
    vector<T> data;
public:
    void push(T x)     { data.push_back(x); }
    T    peek() const  { return data.back(); }
    void pop()         { data.pop_back(); }
    bool empty() const { return data.empty(); }
};

Stack<int>    si;  si.push(42);
Stack<string> ss;  ss.push("hello");
Java — Generics

class Stack<T> {
    private List<T> data = new ArrayList<>();

    public void push(T x)  { data.add(x); }
    public T    peek()     { return data.get(data.size()-1); }
    public void pop()      { data.remove(data.size()-1); }
    public boolean empty() { return data.isEmpty(); }
}

Stack<Integer> si = new Stack<>();  si.push(42);
Stack<String>  ss = new Stack<>();  ss.push("hello");
C++ vs Java
C++: sinh mã riêng cho từng kiểu T → nhanh hơn, nhưng có thể code bloat.
Java: một bản bytecode dùng chung (type erasure) → nhỏ gọn hơn.

Tham chiếu treo
(Dangling Reference)


int* p = malloc(sizeof(int));
*p = 5;
int* q = p; // q và p cùng trỏ một vùng

free(p);    // giải phóng vùng nhớ
p = NULL;   // p được đặt NULL — an toàn

*q = 10;    // ⚠️ NGUY HIỂM!
            // q vẫn giữ địa chỉ cũ
            // vùng đó đã được tái sử dụng!
Trạng thái sau free(p):
p = NULL
✓ an toàn
q → 0x100
freed!
Vấn đề: q đúng kiểu, không NULL — nhưng trỏ vào vùng đã tái sử dụng. Lỗi không bị bắt lúc biên dịch.

Phát hiện tham chiếu treo: Locks & Keys 🔑

Không cần tầng gián tiếp — con trỏ mang key, đối tượng có lock. Dereference kiểm tra key == lock:

Dereference hợp lệ
ptr p
addr = 0x100
key = 42
→
heap[0x100]
lock = 42
data...
key == lock ✓ OK
Sau free & tái cấp phát
ptr p
addr = 0x100
key = 42
→
heap[0x100]
lock = 99
new data
key ≠ lock ✗ ERROR!
So sánh với Tombstone
Tombstone: cần bộ nhớ riêng cho tombstone, dereference 2 bước.
Locks & Keys: key tốn thêm bộ nhớ trong mỗi con trỏ, nhưng dereference chỉ 1 bước.

Rác bộ nhớ & Garbage Collection


int* p = malloc(sizeof(int));
*p = 5;

p = NULL;    // con trỏ DUY NHẤT tới đối tượng mất đi
             // → đối tượng không tiếp cận được
             // → "rác", nhưng vùng nhớ chưa thu hồi!
Memory leak: lặp lại → bộ nhớ cạn dần dù chương trình vẫn chạy.
GC = 2 bước:
① Phát hiện rác
Xác định đối tượng nào không còn tiếp cận được từ root set
② Thu hồi bộ nhớ
Trả vùng nhớ của rác về heap để tái sử dụng
Java, Python, Go, JavaScript — đều dùng GC

Đếm tham chiếu
(Reference Counting)

Mỗi đối tượng có bộ đếm. Counter = 0 → giải phóng ngay:

✅ Trường hợp bình thường

a = [1, 2, 3] # RC = 1
b = a         # RC = 2
b = None      # RC = 1
a = None      # RC = 0 → freed ngay!
Python (CPython), Swift ARC dùng RC
❌ Vấn đề: chu trình tham chiếu

x = {}; y = {}
x['y'] = y    # RC(y) = 2
y['x'] = x    # RC(x) = 2

del x         # RC(x) = 1  ≠ 0
del y         # RC(y) = 1  ≠ 0
# x, y → KHÔNG bao giờ freed!
Python bổ sung cycle detector riêng để xử lý

6 điều cần nhớ

1 Kiểu dữ liệu
Kiểu không chỉ là bit — là hợp đồng về ý nghĩa, thao tác hợp lệ, và lỗi bị bắt sớm.
2 Cấu trúc dữ liệu
Row-major + Dope Vector: mảng đa chiều vừa hiệu quả cache vừa hỗ trợ hình dạng động.
3 Tương đương kiểu
Name vs Structural: hai triết lý. Duck typing: nếu nó hoạt động như một kiểu — thì nó là kiểu đó.
4 Đa hình
Ad-hoc, Parametric, Subtype — ba cách viết code dùng cho nhiều kiểu mà không lặp lại.
5 ADT & Module
Ẩn biểu diễn → độc lập biểu diễn: đổi cài đặt thoải mái, client không cần sửa gì.
6 Bộ nhớ
Không có giải pháp miễn phí: thủ công → nguy hiểm; GC → an toàn nhưng đánh đổi thời gian & bộ nhớ.

Câu hỏi thảo luận

① 1–3 · Triết lý hệ thống kiểu
Python: 1 + "a" → lỗi runtime. JavaScript: 1 + "a" → "1a" (hợp lệ!). TypeScript: lỗi compile-time.
Ba ngôn ngữ, ba cách xử lý coercion. Cái nào an toàn nhất? Cái nào tiện nhất? Hai tiêu chí này có mâu thuẫn không?
② 4–5 · Đa hình và Abstraction
std::vector<int> trong C++ vừa là Generic Module (template), vừa là ADT.
Hãy xác định 5 thành phần ADT của vector. Tại sao vector an toàn hơn mảng C thuần int arr[]?
③ 6 · Quản lý bộ nhớ không cần GC và không cần free
Rust không có GC và không có free thủ công — nhưng vẫn đảm bảo không có dangling reference và memory leak.
