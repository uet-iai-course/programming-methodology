1.
Lập trình hàm (FP) và hướng đối tượng (OOP)

Bản chất của Tính toán (Section 11.1)

Mô hình Mệnh lệnh (Imperative/OOP)

  • Computing with State: Dựa trên thay đổi nội dung ô nhớ qua phép gán ($Assignment$).
  • Trạng thái (State): Giá trị biến phụ thuộc vào trình tự thời gian thực thi.
  • Đơn vị: Đối tượng = Dữ liệu + Hành vi.

Mô hình Hàm (Functional)

  • Computing without State: Tính toán là việc đánh giá các biểu thức toán học.
  • Môi trường (Environment): Giá trị biểu thức chỉ phụ thuộc vào ngữ cảnh định nghĩa, không phụ thuộc thời gian.
  • Đơn vị: Hàm thuần khiết (Pure Function).
[Image of functional programming vs object oriented programming]

Tính minh bạch tham chiếu (Referential Transparency)

Đây là đặc điểm quan trọng nhất của FP được nêu trong sách:

"Một biểu thức được gọi là minh bạch tham chiếu nếu giá trị của nó chỉ phụ thuộc vào giá trị các tham số truyền vào và môi trường cố định, không tạo ra hiệu ứng lề (side effects)."
OOP: obj.increment()
Kết quả trả về khác nhau tùy vào giá trị hiện tại của obj.
FP: add(5, 10)
Luôn trả về 15 dù gọi ở bất kỳ thời điểm nào trong chương trình.

2.
Các mẫu xử lý dữ liệu đặc trưng trong FP

Higher-order Schemata (Section 11.3.4)

Lập trình hàm thay thế vòng lặp thủ công bằng các lược đồ bậc cao để quản lý sự phức tạp:

Mẫu (Pattern) Mô tả toán học Mục đích
Map $L' = [f(x) \mid x \in L]$ Biến đổi dữ liệu gốc sang dạng mới ($1:1$).
Filter $L' = [x \in L \mid P(x)]$ Giữ lại các phần tử thỏa mãn điều kiện $P$.
Fold (Reduce) $res = f(...f(f(init, x_1), x_2)...)$ Tích lũy danh sách thành một giá trị duy nhất.

Tại sao không dùng vòng lặp?

Vòng lặp (Imperative):
  • Phải quản lý biến đếm $i$.
  • Dễ lỗi "Off-by-one" (truy cập ngoài vùng nhớ).
  • Mô tả Cách làm (How).
Patterns (Functional):
  • Tự động hóa việc duyệt (Abstraction).
  • An toàn với dữ liệu bất biến.
  • Mô tả Cái muốn đạt được (What).

3.
Ứng dụng Lambda và STL Algorithms trong C++

Ánh xạ lý thuyết vào C++ STL

Thư viện chuẩn C++ hiện thực hóa các Schemata thông qua các Generic Algorithms:

FP Pattern C++ STL Function Ghi chú chuyên sâu
Map std::transform Yêu cầu Output Iterator.
Filter std::copy_if Sử dụng Predicate để quyết định sao chép.
Fold / Reduce std::accumulate Nằm trong thư viện <numeric>.
Traverse std::for_each Thực thi side effect có kiểm soát.

Sức mạnh của Closure trong Algorithms

Sử dụng Lambda để "đóng gói" môi trường khi thực thi Algorithm:


int limit = 100;
std::vector<int> results;

// Filter: Chỉ lấy các giá trị > limit (capture limit từ môi trường)
std::copy_if(input.begin(), input.end(), 
             std::back_inserter(results), 
             [limit](int x) { return x > limit; });

// Fold: Tính tổng với một giá trị khởi tạo (init)
int total = std::accumulate(results.begin(), results.end(), 0);

4.
Thực hành xây dựng pipeline và tổ hợp hàm

Tổ hợp hàm (Function Composition)

Thay vì viết $f(g(h(x)))$ lồng nhau khó đọc, FP hướng tới việc nối chuỗi:

Input $\rightarrow$ Filter $\rightarrow$ Map $\rightarrow$ Reduce $\rightarrow$ Output 

#include <ranges> 

auto results = numbers 
             | std::views::filter([](int n) { return n % 2 == 0; }) 
             | std::views::transform([](int n) { return n * n; });

// Kết quả chỉ được tính toán khi ta thực sự duyệt kết thúc (Lazy Evaluation)

Lazy Evaluation (Đánh giá trì hoãn)

Một khái niệm then chốt trong FP hiện đại giúp tối ưu hóa hiệu năng:

  • Các thao tác trong Pipeline không thực hiện ngay lập tức.
  • Dữ liệu chỉ "chảy" qua các bộ lọc khi có yêu cầu truy xuất (ví dụ: vòng lặp for).
  • Lợi ích: Có thể làm việc với các dãy số vô tận hoặc tập dữ liệu cực lớn mà không tốn bộ nhớ tạm.

Tổng kết và Đánh giá

Đánh giá mô hình FP

Ưu điểm:

  • Readability: Code ngắn gọn, gần với ngôn ngữ tự nhiên/toán học.
  • Dependability: Dễ dàng chứng minh tính đúng đắn toán học do không có state mutation.
  • Concurrency: An toàn tuyệt đối khi chạy đa luồng (không lo Data Race).

Thách thức:

  • Yêu cầu tư duy trừu tượng cao hơn.
  • Hiệu năng có thể bị ảnh hưởng do cấp phát bộ nhớ cho các bản sao dữ liệu (tuy nhiên C++ hiện đại đã tối ưu hóa bằng Move Semantics).

Lời kết: Đa mô hình (Multi-paradigm)

C++ không bắt buộc bạn phải chọn giữa FP hay OOP:

"Hãy dùng OOP để xây dựng kiến trúc hệ thống, quản lý tài nguyên và trạng thái lớn. Hãy dùng FP để thực thi các thuật toán biến đổi dữ liệu một cách an toàn và minh bạch."

Trân trọng cảm ơn các em đã theo dõi!
