1.
Chương trình con

Trừu tượng hóa điều khiển

  • Trừu tượng hóa (abstraction): che giấu chi tiết để làm rõ bản chất.
  • Trong ngôn ngữ lập trình, có hai nhóm cơ chế:
    • Trừu tượng hóa điều khiển (control abstraction): che giấu “dữ liệu thủ tục/hàm”.
    • Trừu tượng hóa dữ liệu (data abstraction): che giấu cách cài đặt kiểu dữ liệu.
  • Chương này tập trung vào điều khiển: chương trình con, truyền tham số, hàm bậc cao, ngoại lệ.

Chương trình con

Định nghĩa
Chương trình con (subprogram/thủ tục/hàm) là đoạn mã có tên, có môi trường cục bộ, và trao đổi thông tin với phần còn lại của chương trình thông qua tham số.

Cấu trúc của hàm


int foo (int n, int a) { // Header
  int tmp = a;           // Body
  if (tmp == 0) return n;
  else return n + 1;
}
  • Định nghĩa (definition): Gồm phần đầu (header) và thân (body).
  • Sử dụng (call): Kích hoạt hàm với các giá trị cụ thể.

Ba kênh trao đổi thông tin

  • Tham số: truyền dữ liệu vào/ra theo lời gọi.
  • Giá trị trả về: kết quả của hàm (kèm return kết thúc thực thi hiện tại).
  • Môi trường phi cục bộ (nonlocal environment): đọc/ghi biến không cục bộ đang “nhìn thấy”.

Tham số hình thức vs thực tế

  • Tham số hình thức (formal parameters): xuất hiện trong định nghĩa hàm.
  • Tham số thực tế (actual parameters): xuất hiện trong lời gọi.

Biến tĩnh trong hàm

Định nghĩa
Một biến cục bộ có thể được khai báo để giữ giá trị qua nhiều lần gọi (C: static). Biến có vòng đời “gần như toàn chương trình” nhưng không nhìn thấy từ bên ngoài hàm. 

int how_many_times(){
  static int count;
    /* C bảo đảm biến static được
       khởi tạo bằng 0 ở lần
       kích hoạt đầu tiên của hàm */
  return count++;
}

Trừu tượng hóa chức năng

Định nghĩa
Có trừu tượng hóa chức năng (functional abstraction) khi “khách hàng” của hàm chỉ phụ thuộc vào header (tên, tham số, kiểu trả về), không phụ thuộc vào thân hàm.

Trừu tượng hóa chức năng

  • Ý nghĩa: Thay thân hàm bằng phiên bản cùng ngữ nghĩa (vd tối ưu) mà hệ thống vẫn “trong suốt”.
  • Ba việc đặc tả – cài đặt – sử dụng có thể tương đối độc lập.
Ghi nhớ
Lạm dụng môi trường phi cục bộ để trao đổi dữ liệu sẽ phá vỡ trừu tượng hóa chức năng.

2.
Cơ chế truyền tham số

Tổng quan

Định nghĩa
Kỷ luật truyền tham số (parameter passing discipline) mô tả cách ghép tham số thực ↔ tham số hình thức và ngữ nghĩa thu được.
  • Câu hỏi: dữ liệu được chép, dùng chung, hay chép ngược khi kết thúc?

Tổng quan

Phân loại theo hướng giao tiếp
  • Tham số vào (input): chỉ truyền từ bên gọi → hàm, vd: truyền tham trị, truyền hằng.
  • Tham số ra (output): chỉ truyền từ hàm → bên gọi, vd: truyền kết quả.
  • Tham số vào/ra (input/output): truyền hai chiều, vd: truyền trị–kết quả, truyền tham chiếu.

Truyền tham trị

Định nghĩa
Truyền tham trị (call by value): khi gọi hàm, đánh giá tham số thực tế lấy giá trị (r-value) và sao chép vào một biến cục bộ mới (tham số hình thức).
  • Trong khi chạy: không có liên kết giữa tham số hình thức và tham số thực.
  • Chi phí: có thể đắt nếu sao chép cấu trúc lớn (trừ trường hợp chỉ sao chép con trỏ).

Ví dụ truyền tham trị (C++)


void increment(int x) {
  x = x + 1;  // chỉ sửa bản sao cục bộ
}

int main() {
  int a = 5;
  increment(a);
  // a vẫn bằng 5 (không thay đổi)
}
  • Giá trị của a được sao chép vào x.
  • Sửa x không ảnh hưởng đến a.

Truyền tham chiếu

Định nghĩa
Truyền tham chiếu (call by reference): tham số thực tế phải có địa chỉ (l-value); tham số hình thức trở thành một bí danh (alias) của tham số thực.
  • Hệ quả: sửa tham số hình thức ⇔ sửa biến gốc ở bên gọi ⇒ vào/ra.
  • Chi phí: gọi rẻ (lưu địa chỉ), mỗi truy cập thêm một bước gián tiếp.

Truyền tham chiếu trong C++


// C++ có tham chiếu thật với ký hiệu &
void swap(int& x, int& y) {
  int temp = x;
  x = y;
  y = temp;
}
int a = 1, b = 2;
swap(a, b);   // gọi trực tiếp, không cần &a
// a = 2, b = 1
  • Dấu & trong khai báo tham số tạo ra bí danh thật — không cần truyền địa chỉ tường minh khi gọi.
  • C không có tham chiếu như vậy; phải dùng con trỏ (int *a) và truyền địa chỉ (&a) để mô phỏng.
C chỉ có truyền tham trị. C++ bổ sung tham chiếu thật (&). Đây là hai cơ chế khác nhau — không nên nhầm lẫn.

Truyền hằng

Định nghĩa
Truyền hằng (call by constant): ngữ nghĩa như truyền tham trị nhưng tham số hình thức bị ràng buộc tĩnh: không được sửa trong thân hàm. Hệ thống có thể chọn cách cài đặt: dữ liệu nhỏ → sao chép, dữ liệu lớn → truyền tham chiếu (không sao chép).

Ví dụ truyền hằng (C++)


// const & : ngữ nghĩa "chỉ đọc", cài đặt bằng tham chiếu (không sao chép)
void print_info(const std::string& s) {
    std::cout << s << std::endl;
    // s = "khác";  // ❌ lỗi biên dịch: không được sửa tham số hằng
}

// const (tham trị): dữ liệu nhỏ — sao chép, nhưng không cho sửa
void show(const int x) {
    std::cout << x << std::endl;
    // x = 99;  // ❌ lỗi biên dịch
}

std::string name = "Alice";
print_info(name);   // không sao chép chuỗi, chỉ truyền địa chỉ
show(42);           // 42 được sao chép vào x
  • const &: dùng cho dữ liệu lớn — tránh sao chép, vẫn đảm bảo không sửa được.
  • const (tham trị): dùng cho dữ liệu nhỏ (int, double…) — sao chép rẻ, cấm sửa.
  • Trình biên dịch kiểm tra tĩnh: mọi lần gán vào tham số hằng đều bị từ chối ngay lúc biên dịch.

Truyền theo đối tượng

Định nghĩa
Trong các ngôn ngữ dùng mô hình tham chiếu cho biến (Python, Java với kiểu lớp), truyền tham trị thực chất là truyền tham chiếu tới đối tượng — không phải tới biến. Còn gọi là call by assignment hay call by sharing.

Ví dụ Python: kiểu không đổi được


def increment(x):
    x = x + 1   # tạo đối tượng mới, rebind x cục bộ

a = 5
increment(a)
print(a)   # vẫn là 5 — giống call by value!
  • Số nguyên (int) là immutable.
  • Gán lại x chỉ thay đổi liên kết cục bộ, không ảnh hưởng a.

Ví dụ Python: kiểu đổi được


def append_zero(lst):
    lst.append(0)   # sửa đối tượng được chia sẻ

L = [1, 2, 3]
append_zero(L)
print(L)   # [1, 2, 3, 0] — L bị thay đổi!
  • List (list) là mutable.
  • Hàm và bên gọi chia sẻ cùng một đối tượng — sửa nội dung thì thấy ở cả hai.
Không thể mô phỏng đúng truyền tham chiếu trong Python — ta chỉ có thể thay đổi nội dung đối tượng, không thể đổi biến nào bên gọi đang trỏ tới.

So sánh nhanh

Chế độ Truyền cái gì? Sửa formal → ảnh hưởng actual? Sửa nội dung → ảnh hưởng actual?
Tham trị (C) Bản sao giá trị Không N/A
Tham chiếu (C++ &) Địa chỉ biến Có Có
Theo đối tượng (Python) Tham chiếu đối tượng Không Có (nếu mutable)

Truyền kết quả

Định nghĩa
Truyền kết quả (call by result): tham số hình thức là biến cục bộ mới; tham số thực tế phải cho ra l-value. Khi hàm kết thúc, chép ngược giá trị từ hình thức về vị trí của tham số thực.
  • Đây là chế độ chỉ ra (output-only).
  • Cần quy ước: xác định l-value lúc gọi hay lúc kết thúc? nếu nhiều tham số kết quả thì chép ngược theo thứ tự nào?

Ví dụ truyền kết quả (Ada)


procedure Init(x : out Integer) is
begin
  x := 42;  -- gán giá trị cho tham số hình thức
end Init;

-- Sử dụng:
a : Integer;       -- a chưa được khởi tạo
Init(a);           -- sau lời gọi, a = 42
  • Từ khóa out trong Ada đánh dấu tham số là chỉ ra.
  • Giá trị ban đầu của a không được truyền vào hàm.
  • Khi hàm kết thúc, giá trị của x được chép ngược về a.

C++: mô phỏng truyền kết quả

C++ không có truyền kết quả như Ada. Ta thường mô phỏng tham số chỉ ra bằng cách truyền địa chỉ (con trỏ) và ghi vào ô nhớ đó. 

void Init(int* x) {        // x nhận địa chỉ (l-value) của biến bên ngoài
  *x = 42;                 // ghi trực tiếp vào biến được trỏ tới
}

// Sử dụng:
int a;                     // a có thể chưa khởi tạo
Init(&a);                  // sau lời gọi, a = 42
  • &a: lấy địa chỉ của a; *: giải tham chiếu để ghi giá trị.
  • So sánh với Ada out: mục tiêu giống “chỉ ra”, nhưng cơ chế là truyền tham trị của địa chỉ.

Truyền trị–kết quả

Định nghĩa
Truyền trị–kết quả (call by value-result): chép vào khi gọi (như tham trị) và chép ra khi kết thúc (như kết quả).
  • Giao tiếp hai chiều, nhưng trong khi chạy vẫn làm việc trên biến cục bộ.
  • Một số ngôn ngữ có thể cài đặt bằng tham chiếu cho dữ liệu lớn, nhưng cần cẩn thận về ngữ nghĩa.

Ví dụ truyền trị–kết quả (Ada)


procedure Double(x : in out Integer) is
begin
  x := x * 2;  -- làm việc trên bản sao cục bộ
end Double;

-- Sử dụng:
a : Integer := 5;
Double(a);         -- sau lời gọi, a = 10
  • Từ khóa in out trong Ada đánh dấu tham số vào/ra.
  • Chép vào: giá trị của a (= 5) được sao chép vào x.
  • Chép ra: khi hàm kết thúc, giá trị của x (= 10) được chép ngược về a.

Trị–kết quả ≠ Tham chiếu

Hai chế độ cho kết quả khác nhau khi có bí danh (aliasing).


void foo (/* x, y */ int x, int y, int b) {
    if (x == y) b = 1;
    else        b = 2;
}

int a = 3, b = 0;
foo(a, a, b);   // gọi với hai tham số đầu là cùng biến a

Điều kiện x == y cho kết quả gì? Phụ thuộc vào chế độ truyền!

Phân tích: Truyền trị–kết quả

  • Khi gọi: chép a=3 vào hai biến cục bộ riêng biệt x và y.
  • Không có bí danh: x == y là 3 == 3 → true → b = 1.
  • Khi kết thúc: chép ngược x → a, y → a, b → biến b bên gọi = 1.

Phân tích: Truyền tham chiếu

  • Khi gọi: x và y đều là bí danh của a.
  • Điều kiện x == y thực chất là a == a → luôn true → b = 1.
  • Trong ví dụ này kết quả trùng nhau — nhưng xét ví dụ sau:

void bar (int x, int y) {
    x = x + 1;          // x (= a) tăng lên 4
    if (x == y)         // Trị–kết quả: 4 == 3? → false → write(0)
        write(1);       // Tham chiếu:  4 == 4? → true  → write(1)
    else
        write(0);
}
int a = 3;
bar(a, a);
Truyền trị–kết quả: in ra 0 (không có bí danh, y giữ nguyên = 3).
Truyền tham chiếu: in ra 1 (x và y cùng là a, thay đổi x tức thay đổi y).

C++: mô phỏng trị–kết quả


void Double_copy(int a_in, int* a_out) {   // copy-in
  int x = a_in;                            // bản sao cục bộ
  x = x * 2;
  *a_out = x;                              // copy-out
}

int a = 5;
Double_copy(a, &a);   // a = 10
  • Chép vào: a_in nhận giá trị của a.
  • Chép ra: ghi x về a qua con trỏ.

3.
Truyền theo tên

Nguồn gốc và Ý tưởng

  • Được giới thiệu lần đầu trong ngôn ngữ ALGOL 60.
  • Gần đây xuất hiện trở lại trong các ngôn ngữ hiện đại như Scala hoặc thông qua biểu thức lambda.
  • Ý tưởng cốt lõi: Không đánh giá tham số ngay lập tức. Thay vào đó, tham số thực sự được "thế chỗ" trực tiếp vào thân hàm.
Quy tắc sao chép (Copy Rule)
Lời gọi hàm tương đương ngữ nghĩa với việc thực thi thân hàm, trong đó mọi lần xuất hiện của tham số hình thức được thay thế bằng văn bản của tham số thực sự.

Vấn đề "Bắt biến" (Variable Capture)

Xét ví dụ:


int x = 0;
int foo (name int y) {
    int x = 2;
    return x + y;
}
// ...
int a = foo(x + 1);

Nếu thay thế mù quáng: return x + (x + 1) trong môi trường của foo sẽ lấy x=2. Kết quả là 5 (Sai!).

Ngữ nghĩa đúng: Tham số thực sự (x + 1) phải được đánh giá trong môi trường của bên gọi (nơi x = 0). Kết quả đúng phải là 3.

Đặc điểm: Đánh giá khi cần (By Need)

  • Tham số chỉ được đánh giá khi và chỉ khi nó thực sự được gặp trong quá trình thực thi.
  • Nếu gặp nhiều lần, nó sẽ được đánh giá lại bấy nhiêu lần.

Đặc điểm: Đánh giá khi cần (By Need)

Ví dụ về Tác dụng phụ 

int i = 2;
int fie (name int y) { return y + y; }
// ...
int a = fie(i++);

Lệnh y + y trở thành (i++) + (i++).
Lần 1: i=2, sau đó i thành 3.
Lần 2: i=3, sau đó i thành 4.
Kết quả: a = 5, i = 4.

So sánh với Truyền bằng trị-kết quả

Truyền bằng tên không phải là cách gọi khác của Truyền bằng trị-kết quả.


void fiefoo (name int x, name int y) {
    x = x + 1;
    y = 1;
}
// ...
int i = 1; int A[5]; A[1] = 4;
fiefoo(i, A[i]);
Truyền bằng trị-kết quả
Kết thúc: i=2, A[1]=1. Các phần tử khác của mảng A không đổi.
Truyền bằng tên
Thân hàm thành:
i = i + 1; (i thành 2)
A[i] = 1; (tương đương A[2] = 1)
Kết quả: i=2, A[1]=4, A[2]=1.

Cài đặt

Để tránh lỗi "bắt biến", bên gọi không chỉ truyền biểu thức mà truyền một cặp (biểu thức, môi trường), gọi là một Bao đóng (Closure).

  • Môi trường này chứa tất cả các biến tự do có trong biểu thức tại thời điểm gọi.
  • Trong ALGOL 60, cấu trúc này được gọi là một Thunk (một hàm không đối số đi kèm môi trường của nó).

Cài đặt

Ứng dụng: Jensen's Device

Tận dụng tác dụng phụ để viết mã nguồn cực kỳ gọn nhẹ cho các công thức toán học.


int summation (name int exp, name int i, int start, int stop) {
    int acc = 0;
    for (i = start; i <= stop; i++)
        acc = acc + exp; // exp được tính lại mỗi khi i thay đổi
    return acc;
}
// ...
// Tính tổng 2x^2 - 2x + 1 với x từ 1 đến 10
y = summation(2*x*x - 2*x + 1, x, 1, 10);

Kết quả tương đương với biểu thức: \(y = \sum_{x=1}^{10} (2x^2 - 2x + 1)\).

Nhận xét: Truyền theo tên

  • Ưu điểm: Rất linh hoạt, mạnh mẽ.
  • Nhược điểm:
    • Chi phí thực hiện cao do phải đánh giá biểu thức nhiều lần.
    • Mã nguồn khó hiểu, khó bảo trì do các tác dụng phụ khó lường.

Bài tập: Truyền theo tên

Cho đoạn mã sau (ngôn ngữ giả, name = truyền theo tên):


int X = 2;

void foo (name int Y) {
    X++;        // (1)
    write(Y);   // (2)
    X++;        // (3)
}

foo(X + 1);
write(X);       // (4)

Hỏi: Lệnh (2) in ra giá trị nào? Lệnh (4) in ra giá trị nào?

Đáp án

  • Theo quy tắc sao chép: mọi lần gặp Y trong thân hàm → thay bằng biểu thức X + 1 trong môi trường bên gọi.
  • (1) X++ → X = 3.
  • (2) write(Y) → đánh giá X + 1 với X = 3 → in ra 4.
  • (3) X++ → X = 4.
  • (4) write(X) → in ra 4.
Tham số Y được đánh giá tại thời điểm sử dụng, không phải lúc gọi hàm. Kết quả phụ thuộc vào trạng thái X ngay trước lần đánh giá đó.

4.
Hàm bậc cao

Hàm bậc cao

Định nghĩa
Một ngôn ngữ lập trình được coi là hỗ trợ hàm bậc cao khi nó cho phép hàm:
  • Được truyền vào như một tham số của hàm khác.
  • Được trả về dưới dạng kết quả từ một hàm khác.

Đây là cơ chế cốt lõi của các ngôn ngữ lập trình hàm, giúp tăng tính mô-đun hóa và trừu tượng hóa.

Hàm đóng vai trò tham số

Xét ví dụ: Hàm f được truyền vào hàm g và được gọi thông qua tên tham số hình thức h.


{ int x = 1;
  int f(int y) { return x + y; }
  void g (int h(int b)) {
    int x = 2;
    return h(3) + x;
  }
  { int x = 4;
    int z = g(f); // f được truyền vào g
  }
}

Vấn đề: Khi f được gọi qua h, biến x trong f sẽ lấy giá trị nào (1, 2, hay 4)?

Chính sách Ràng buộc (Binding)

Có hai cách để chọn môi trường phi cục bộ cho hàm khi nó được truyền đi:

Phân loại
  • Ràng buộc sâu (Deep binding): Sử dụng môi trường đang hoạt động tại thời điểm liên kết giữa tham số hình thức và hàm được tạo ra (lúc gọi g(f)).
  • Ràng buộc nông (Shallow binding): Sử dụng môi trường đang hoạt động tại thời điểm hàm thực sự được gọi (lúc thực hiện h(3) bên trong g).

Hầu hết các ngôn ngữ dùng phạm vi tĩnh đều sử dụng ràng buộc sâu.

Kết quả phân tích ví dụ

Phạm vi (Scope) Ràng buộc (Binding) Giá trị x sử dụng Kết quả g trả về
Tĩnh Sâu x = 1 (môi trường khai báo f) 6
Động Sâu x = 4 (môi trường lúc gọi g(f)) 9
Động Nông x = 2 (môi trường bên trong g) 7

Cài đặt Ràng buộc sâu: Bao đóng

  • Để hỗ trợ ràng buộc sâu, máy ảo không thể chỉ truyền con trỏ mã lệnh của hàm.
  • Nó phải truyền một Bao đóng (Closure): Cặp (con trỏ mã lệnh, con trỏ môi trường).

Cài đặt Ràng buộc sâu: Bao đóng

Khi f được gọi qua h, máy ảo lấy con trỏ môi trường từ bao đóng để thiết lập chuỗi tĩnh (static chain) cho bản ghi kích hoạt mới.

Hàm đóng vai trò kết quả

Hàm có thể tạo ra và trả về một hàm khác tại thời điểm chạy.


void->int F() {
    int x = 1;        // x là biến cục bộ của F
    int g() { return x + 1; }
    return g;         // trả về bao đóng của g
}

void->int gg = F();   // F đã kết thúc!
int z = gg();         // gọi g sau khi F chết

Vấn đề "Funarg ngược": Môi trường của g chứa x là biến cục bộ của F.

Vấn đề Tham chiếu Treo

  • Theo kỷ luật ngăn xếp, khi F kết thúc, bản ghi kích hoạt của nó bị hủy.
  • Lúc này, bao đóng của gg trỏ vào một vùng nhớ không còn hợp lệ.

Tại sao ngăn xếp không đủ?

Khi F() đang chạy
Act Rec của F
x = 1
← bao đóng của g trỏ vào đây
Act Rec của main
Sau khi F() kết thúc
Act Rec của F (đã hủy)
x = ??? ← tham chiếu treo!
Act Rec của main

Giải pháp: Cấp phát trên Heap

  • Thay vì dùng ngăn xếp, bản ghi kích hoạt được cấp phát trên heap.
  • Bao đóng giữ một con trỏ tới bản ghi kích hoạt trên heap — bản ghi này không bị hủy khi hàm kết thúc.
  • Garbage Collector (GC) chỉ thu hồi bộ nhớ khi không còn bao đóng nào tham chiếu tới nữa.
Đây là lý do Python, Java, Scala, JavaScript cần GC. C++ tránh vấn đề này bằng cách cấm hàm lồng.

Biểu thức Lambda

  • Nhiều ngôn ngữ hiện đại cho phép định nghĩa hàm "ẩn danh" (không tên).
  • Ví dụ Python: lambda x: x * x
  • Ví dụ Scala: (x: Double) => x * x
  • Cài đặt: Vẫn sử dụng bao đóng vì thân hàm lambda thường chứa các tên biến từ môi trường bên ngoài.

Bao đóng xuất hiện ở đâu?

Tình huống Tại sao cần bao đóng?
Truyền theo tên Tham số thực tế phải được đánh giá trong môi trường của bên gọi, không phải bên được gọi
Hàm làm tham số (deep binding) Hàm được truyền đi cần "mang theo" môi trường lúc nó được định nghĩa
Hàm làm kết quả Hàm trả về có thể tham chiếu biến cục bộ của hàm gọi — cần giữ môi trường đó sống
Biểu thức Lambda Hàm ẩn danh thường chứa biến từ phạm vi bên ngoài

Tại sao C không cần bao đóng?

  • C không cho phép định nghĩa hàm lồng nhau.
  • Mọi hàm đều ở mức toàn cục → không có biến tự do phi cục bộ.
  • Để truyền hàm làm tham số: chỉ cần con trỏ hàm (function pointer) — không cần con trỏ môi trường.

// C: truyền hàm qua function pointer — không cần closure
int square(int x) { return x * x; }

int apply(int (*f)(int), int val) {
    return f(val);   // f chỉ là địa chỉ mã lệnh
}

int result = apply(square, 5);  // = 25

Ngược lại, Python/Scala/Java luôn dùng bao đóng vì cho phép hàm lồng và lambda.

5.
Xử lý ngoại lệ

Ngoại lệ là gì?

Định nghĩa
Ngoại lệ (exception) là một sự kiện xảy ra trong quá trình thực thi chương trình làm gián đoạn luồng điều khiển bình thường.
  • Lỗi ngữ nghĩa động (chia cho 0, tràn bộ nhớ).
  • Tình huống đặc biệt do người lập trình tự định nghĩa.
  • Mục đích: Chuyển điều khiển tới một điểm khác để xử lý lỗi một cách cấu trúc.

Cơ chế xử lý (Try-Catch-Throw)

  • Throw/Raise: Kích hoạt ngoại lệ.
  • Try block: Đánh dấu vùng mã nguồn được bảo vệ.
  • Catch/Handler: Đoạn mã thực hiện xử lý khi ngoại lệ tương ứng xảy ra.

try {
  val = average(myArray);
} catch (const EmptyArrayException& e) {
  cout << "Mảng rỗng!" << endl;
}

Lan truyền ngoại lệ

  • Nếu ngoại lệ không được xử lý trong hàm hiện tại, nó sẽ lan truyền ngược theo chuỗi gọi hàm (dynamic chain).
  • Quá trình này tiếp tục cho đến khi tìm thấy một khối catch phù hợp hoặc đạt đến trình xử lý mặc định của hệ thống (làm sập chương trình).
  • Khác với phạm vi biến (tĩnh), ngoại lệ tìm trình xử lý theo phạm vi động.

Cài đặt ngoại lệ

Thách thức: xử lý ngoại lệ cần đúng nhưng cũng phải không gây chi phí trong luồng thực thi bình thường.

Chiến lược 1: Dựa trên ngăn xếp

Cách hoạt động
  • Khi vào khối try: đẩy con trỏ handler lên ngăn xếp.
  • Khi ra bình thường: lấy con trỏ handler ra.
  • Khi có ngoại lệ: tra ngăn xếp, nhảy tới handler.
Đánh giá
  • ✅ Đơn giản để cài đặt.
  • ✅ Nhanh khi có ngoại lệ.
  • ❌ Tốn chi phí ngay cả khi không có lỗi — mỗi lần vào/ra try đều thao tác ngăn xếp.

Chiến lược 2: Dựa trên bảng

Cách hoạt động
  • Trình biên dịch tạo bảng Exception Handler (EH): (địa chỉ_đầu, địa chỉ_handler).
  • Khi vào/ra try bình thường: không làm gì.
  • Khi có ngoại lệ: tìm kiếm nhị phân trong bảng EH theo PC hiện tại.
Đánh giá
  • ✅ Chi phí bằng 0 trên đường bình thường.
  • ✅ Được dùng trong C++, Java hiện đại.
  • ❌ Khi có ngoại lệ: chậm hơn O(log n) do phải tìm bảng.
Lý do chọn bảng
Ngoại lệ hiếm xảy ra hơn nhiều so với việc vào/ra khối try. Tối ưu cho trường hợp phổ biến (không lỗi) là lựa chọn đúng đắn.

Minh họa bảng EH

Mã nguồn 

// addr 100
try {
  // addr 104
  foo();
  // addr 120
  bar();
  // addr 136
} catch (X& e) {
  // addr 140 (handler)
  handle(e);
}
// addr 160
Bảng EH sinh ra
ip_start ip_end handler
104 136 140
… (mỗi hàm có một dòng ẩn)

Nếu ngoại lệ tại addr 120: tìm dòng có ip_start ≤ 120 ≤ ip_end → nhảy tới 140.

Ngoại lệ như công cụ điều khiển

Ngoại lệ không chỉ dùng để xử lý lỗi — đôi khi chúng giúp viết mã hiệu quả hơn.

Bài toán: Tính tích các nhãn của cây nhị phân. Nếu có nhãn = 0, tích = 0 ngay lập tức.

Cách 1: Không dùng ngoại lệ


int mul(Tree t) {
    if (t == null) return 1;
    if (t.val == 0) return 0;           // kiểm tra ở MỖI nút
    int left  = mul(t.left);
    if (left == 0) return 0;            // kiểm tra lại sau mỗi lần đệ quy
    int right = mul(t.right);
    if (right == 0) return 0;
    return t.val * left * right;
}
  • Đúng, nhưng kiểm tra điều kiện lặp lại ở mọi nút kể cả khi không có số 0.
  • Không thoát sớm được khi gặp số 0 ở sâu trong cây.

Cách 2: Dùng ngoại lệ để thoát sớm


class Zero {};   // định nghĩa lớp ngoại lệ

int mulAux(Tree t) {
    if (t == null) return 1;
    if (t.val == 0) throw Zero{};   // thoát ngay lập tức!
    return t.val * mulAux(t.left) * mulAux(t.right);
}

int mulEff(Tree t) {
    try {
        return mulAux(t);
    } catch (Zero&) {
        return 0;   // bắt ngoại lệ, trả về 0
    }
}
mulAux không có điều kiện kiểm tra lặp — mã sạch hơn. Khi gặp số 0, ngoại lệ lan truyền ngược toàn bộ ngăn xếp đệ quy một lần duy nhất, bỏ qua mọi tính toán còn lại.

Bạn đã gặp những điều này ở đâu?

Các khái niệm hôm nay không chỉ nằm trong sách — chúng ẩn sau mọi công cụ bạn dùng hằng ngày.
